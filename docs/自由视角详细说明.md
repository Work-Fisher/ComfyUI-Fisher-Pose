# 自由视角模式 · 详细说明

> 本文是 `Fisher Qwen2.1 人物与姿态编码` / `Fisher 机位与姿态` 两个节点（自由视角模式）的完整技术说明。自由姿势模式见仓库首页 README。

## 提示词格式：JSON＋朝向 - 姿势

当前两个节点的提示词STRING输出均为完整JSON，合并编码节点将相同JSON直接传给Qwen正向编码；原有输出口顺序和连线不变。

- `rewritten_prompt`：保留当前完整编辑指令，接PE时保留PE最终扩写正文。
- `posture_description`：按“人物1：朝向 - 姿势描述”逐人换行，动作由编辑器计算；没有人物时为空字符串，仅视角时写保持原动作。
- `wh_ratio`：最终输出宽高的约分比例；`ratio_follow`为空字符串。

这是PE字段结构加自定义姿态字段的组合，不是声称官方要求此扩展。序列化在PE完成或命中缓存之后执行，不增加PE调用。编辑器内显示动作及绑定预览，节点运行后的“实际提示词”是确实送入模型的JSON。

## 无人场景图片魔方

删除全部人物后显示场景魔方，图片面代表正面，其他面标注方向，跟随当前镜头旋转与远近。优先读取reference_image_1上游节点已有预览或LoadImage文件；暂时没有可读上游图时，可在左侧上传。手动上传的缩略图随编辑场景保存。魔方仅作方向示意，不还原图片中的真实三维空间，不进入人偶输出或PE输入。添加人物后隐藏。

## 四肢拉伸与纯场景机位

手腕、脚踝向外拖超过原骨长时自动拉长当前肢体；Alt拖动关节可调整长度（含缩短）。骨长随工作流保存，支持撤销。恢复站姿会恢复默认比例。

允许删除最后一个人物，零人物时自动进入纯场景“仅视角”，仍可拖空白转镜头及调整远近。合并编码节点仅连接reference_image_1作为场景原图；内部不附人偶图，提示词及PE只描述场景机位，不添加人物动作。旧双输出节点仅连接提示词，断开姿态图连线。可随时添加人物回到姿态编辑。此功能改变原场景的观察机位，不会自动删除原图里已有的物体。

## PE复用与身体控制

PE在当前加载的CLIP实例内缓存最近16次成功扩写。人物图片像素、姿态参考图、指令/动作数据、画幅、PE模型和输出上限不变时复用结果；改变采样种子或仅重新打开编辑器不会重新扩写。失败不缓存。重启ComfyUI或重新加载PE模型后需首次扩写，不跨重启保存。

灰色肩部、髋部、胸部和骨盆已支持拖动；头部也可拖动。胸部围绕骨盆带动上身弯腰/侧倾，肩部带动肩带和上肢，骨盆调整尽量保持脚的位置，达到腿长极限时脚会随动。躯干转向同步提示词。拖身体表面仍移动人物；Shift拖关节也可移动整个人。修改可撤销，骨架模式便于选中灰色点。

新版人偶增加收腰肩背轮廓、渐变粗细的四肢和简化手掌，仍为无手指独立控制的素色人偶，保持拍摄框原样输出。

## 当前版本：拍摄框立体人偶参考

输出编辑器拍摄框内的立体人偶画面，使用当前宽高、机位、位置、远近和裁切，不自动框人。去除选中圆环、箭头、名称和上传的背景图。最终生图宽高仍按节点设置；拍摄框外的身体部分不会出现在参考图里；需要全身时请先调整机位或使用「框住所有人」。

更新后重启ComfyUI并刷新网页。已有工作流请打开编辑器，点击「应用到节点」一次，保存新版人偶图。之后无需保持编辑器打开。每次应用都会重新渲染当前姿势，图像和姿态一起保存在工作流中。

首次使用需打开编辑器并应用当前拍摄框；多人时需分别选择照片并重新应用编辑器。PE关闭思考、输入图片最长边1024；断开pe_clip可直接使用本地动作指令。


将整个 `ComfyUI-Fisher-Pose` 文件夹放入 `ComfyUI/custom_nodes/`，重启 ComfyUI，再刷新浏览器。无需安装额外 Python 包或下载模型。节点搜索 `Fisher`。

## Qwen2.1 合并编码节点（推荐）

默认不连接 `pe_clip` 即为直接输出：根据编辑器数据组织“编辑目标→人物与图片对应→保留外观→逐人动作→移除旧动作→机位、背景与风格”的连续自然语言。明确描述上臂/大腿伸展方向、肘膝弯曲程度、手脚相对关节位置，以及小腿内收/外展/跨中线；不写关节角度数值，也不猜测具体衣服或物件名称。图片采用 `<imageN>` 标签，画幅由节点单独控制，包装成下述JSON后直接送正向编码。无需加载PE模型。

搜索 `Fisher Qwen2.1 人物与姿态编码`。它将编辑器、参考图排序和本机 `TextEncodeQwenImage21` 编码合在一起，需要支持该编码器的新版 ComfyUI，以及已有的 Qwen2.1 模型、CLIP 与 VAE。

- 人物图依次接 `reference_image_1/2/3`，每个口一张，不接图片批次。人偶图由编辑器在应用时渲染并保存，节点将其放在最后：三张人物图时人偶参考是 `<image4>`。
- 在编辑器添加相应人数。`person_1/2/3_reference` 对应左侧人物列表顺序。自动模式：仅一张参考图时多人共用它，多张参考图时人物1→图1、人物2→图2、人物3→图3；也可手动选择。共用合照时，在人物页填写“穿红衣的人”等身份描述。
- `正向`、`负向`、`latent` 三个输出分别连接采样器对应入口。内部把生成指令送到正向、负向保持空；画幅由编辑器或 width/height 输入决定，宽高须为16倍数。
- 仅视角自动不附姿态参考图；姿态模式明确替换原姿势、修复原肢体位置，保留人物外观。多图人物组合不把某张图默认当作全体人物的原始合照。
- 编辑器预览显示图片对应关系；运行后从 `实际提示词` 查看真正送进编码器的文字。此节点固定使用 Qwen 中文编辑指令，不使用旧节点的 Multiangle LoRA 格式。
- 编辑器上传的参考图仍仅用于骨架适配；人物外观图必须接到节点的 IMAGE 输入口。

### 与官方 Prompt Rewrite 的关系

编辑指令参考 [Qwen Image 2.1 官方规范](https://github.com/QwenLM/Qwen-Image-2.1/tree/main/prompt_rewrite)，使用 `<imageN>` 标识、明确各图用途、保持未改属性并替换目标动作。未连接 `pe_clip` 时使用确定性指令；连接后实际调用 PE-I2I 看人物图与立体人偶、描述具体动作，再将解析出的最终指令送往生图编码器。不要再通过 `Generate LTX2 Prompt`：它会加入视频专用系统模板。

使用 PE 时需加载 `qwen3.5_qwen_image_2.1_pe_i2i` 模型。生图用的 CLIP 仍接 `clip`，PE 专用 CLIP 接 `pe_clip`，不能交换。

适配器使用用户提供的 `system_prompt_edit.txt`、Qwen3.5 chat 格式，关闭 thinking；全部图片按与生图编码相同顺序输入。直接接收完整 `rewritten_prompt` JSON，兼容旧的已结束思考块。输出截断、引用不存在图片、画幅建议与编辑器冲突时明确停止，不把原始思考文本当提示词。当前固定保留编辑器画幅，检验 `wh_ratio` / `ratio_follow` 与之相符，不偷偷改画幅。

现在由编辑器直接计算每个人相对镜头的朝向、肘膝内夹角及手腕/脚踝相对关节的投影方向，中文预览与后端使用同一套规则。这些数据传给PE作为动作参考，由PE整理成自然语言；不要求逐字保留，也不会因动作描述遗漏或改写而停止生图。

送入PE的所有人物参考图和人偶姿态图，统一等比缩小至最长边不超过1024像素；小图不放大，不裁切、不拉伸，短边按像素取整。此预处理只作用于PE输入，不改变原图或生图画幅。默认输出上限8192 token，采样温度1、top_p .95、top_k20、presence_penalty0，thinking关闭，模板预填空的已结束思考块，直接生成最终结果。`pe_max_tokens` 可调到24000，但会增加显存；截断时不会静默生成。PE会增加等待时间，且不能保证识别所有复杂/裁切/重叠姿势，最终仍需看真实生图结果。

当前单人实测：PE关闭思考，推理约62秒；生图约108秒。人偶图使本样本双臂展开、双膝屈起更接近目标，原持杯动作消失；仍有朝向、服装及最终竖图裁切偏差。仅为此样本结果，不保证任意姿势准确或所有设备同速。

## 原双输出节点的接线（兼容旧工作流）

- 提示词 `STRING` → `TextEncodeQwenImage21.prompt`
- 人偶姿态图 `IMAGE` → `TextEncodeQwenImage21.images.image_2`
- 原始人物图片 → `TextEncodeQwenImage21.images.image_1`

仅视角时只连接提示词口，断开姿态图到 image_2 的连线；仅姿态时可使用节点提示词或自行填写；组合时两个输出都连接。切换节点模式不会自动修改工作流连线。

双击节点不一定打开编辑器，请点击节点里的「打开机位与姿态编辑器」。拖动关节摆姿、拖动空白转机位；设置输出用途与尺寸后点击「应用到节点」，再运行工作流。关闭或取消会放弃本次编辑。场景与镜头收藏随工作流 JSON 保存，节点实例彼此隔离。无需保持编辑器打开，后端直接读取随场景保存的人偶参考图。

`extra_prompt` 是补充要求；不需要经过提示词扩写节点。人偶参考尺寸按应用时的编辑器宽高保存。插件的 `workflows/` 只附带自由姿势工作流，自由视角模式按上面的接线说明自行连接。

## 当前范围

人偶头部采用平面贴图绘制眼睛和“前/后”，没有凸起鼻子；脚下箭头指向人物局部正前方。人物页显示相对镜头朝向并提供“转身180°”，该操作旋转整个人物及姿势，可撤销。二维骨架没有唯一正背面，需要用户依据标记确认。

人物朝向结合实际相机位置、人物位置及 `bodyAngle` 分别计算，不能用全局机位的“背面视角”代替所有人的朝向。编辑器坐标的正前方为局部+Z；头部当前没有独立转向。关节说明区分“人物自身左右”和“画面投影左右”，仅视角模式不添加四肢动作要求。兼容模式的 Multiangle LoRA 原版镜头格式保持不变。

支持 1–3 人：添加/复制/删除、单人选择、各自两段式 IK、转身、地面移动、预设与镜像。左侧选择人物或直接点击人偶；直接拖动身体改变站位，拖动彩色关节摆姿，无需切换模式（Shift 拖关节也可移动整个人物）。所有人物共用相机，导出一张拍摄框内的人偶图。镜头收藏、撤销与工作流保存包含整个多人场景。旧版单人场景自动迁移，原来的两个输出接口不变。

「人物」页可填写“对应原图中的谁”，例如“左侧穿红衣的人”；提示词会依据骨架投影左右位置生成对应关系。这是文字引导，不是人脸自动识别或身份锁定。旧双输出节点使用一张多人合照作为 image_1；三张独立人物图请使用上面的合并编码节点。

上传参考图后可点击「骨架适配人偶」：支持标准彩色 OpenPose 身体骨架图和本插件旧版导出的骨架图，通过身体连接关系过滤手指、面部标记的同色干扰，识别 1–3 人，并同步动作、人物比例与图片构图；识别失败不会修改原场景，可撤销。默认「只改选中的人物」：先选人物，再上传骨架并点击适配；可为每个人依次上传不同姿势，保留其他人物、机位、画幅、名称、身份说明、站位与转身角度。参考图含多人时，第一次识别后需选择从左到右的来源人物，再点击应用。姿势按原人物体量缩放，脚部基准保持。只有选择「按整张图重建场景」才替换全部人物并重设正面机位与画幅。单张图按二维平面初始化，无法还原真实前后深度，侧面姿势需手动调整。普通人物照片不做姿态估计。存在足够身体连接时，可对重叠、裁切关节近似补全，并在界面列出需要检查的部位；这些位置是估算值，并不等于恢复真实深度或原图中不可见的位置。证据不足、配色不同或多人连接歧义仍可能无法识别。

适配结果、各人骨长随工作流保存，后续仍可拖关节、移动和转身；图片本身只作参考叠加，不写入工作流，也不替代 image_1。参考图按输出画框对齐。骨架配色与连接顺序参考 [ControlNet OpenPose 绘制实现](https://github.com/lllyasviel/ControlNet/blob/main/annotator/openpose/util.py)，识别算法为本插件本地实现，不上传图片或下载模型。

## 视角提示词

角度分档和词汇参考 [ComfyUI-qwenmultiangle](https://github.com/jtydhr88/ComfyUI-qwenmultiangle/blob/master/nodes.py)：水平八方位，俯仰阈值 -15/15/45 度，zoom 小于 2 为远景、2–6 为中景、6 及以上为特写。方向以场景正面为基准，90 度对应 right side view，不随选中人物或人物转身改变。

「输出」页选择格式：
- 中文编辑指令：默认，适合现有 Qwen2.1 工作流，采用上述镜头词汇与分档。
- Multiangle LoRA (<sks>)：仅视角模式输出原版格式，如 `<sks> right side view high-angle shot close-up`。需要使用者在下游配置兼容的多视角 LoRA，插件不下载或加载该模型。组合模式追加英文人物/人偶姿态参考说明。

三维相机距离按人物场景尺度实现，未照搬参考项目图片卡片的距离比例。「框住所有人」可进一步拉远镜头，保证多人可见。

人偶不含独立手指动作。Qwen 将人偶图作为姿态参考理解，实际动作/视角遵循度由模型决定；本插件不包含 ControlNet。插件不调用外部 API、不安装或修改其他节点、不修改 ComfyUI 核心。

Three.js 0.182.0 以本地文件提供，许可见 `web/editor/vendor/LICENSE`。姿态编辑器独立实现。镜头术语与分档参考上述 MIT 项目，未复制其节点、Vue 或 Three.js 控件源码。编辑器源码直接位于 `web/editor/studio.mjs`、`state.mjs` 和 `avatar.mjs`，不再从独立原型通过文本替换生成。

## 本地样本验证

已批量运行用户提供的 209 张样本：144 张完整连接匹配，65 张使用近似补全，均能生成有限坐标的可编辑姿势；836 次四肢 IK 拖动检查通过。此统计是生成与可编辑性验证，不是逐关节人工标注的准确率，也不保证任意新图片可识别。

零人物场景以原图机位为水平和俯仰零点，提示词明确输出摄影机左右绕行角度和俯仰角度（精度0.1度），PE按这些参数整理描述。该参数是编辑意图，单张图生成不保证精确三维重建。

纯场景（0人物）先生成新版通用机位提示词，再由已连接的PE结合场景原图扩写，最终编码完整JSON。描述相对原图的环绕方向、角度、近远侧和新露出空间，不写死场景物体。场景与人物模式统一使用已连接的pe_clip；PE关闭思考、输入图片最长边1024及缓存机制保持不变。请在合并编码节点连接pe_clip；未连接时仍兼容直接提示词输出。

## 画布机位模板、PE选项与独立预览
场景机位采用AIFISHER画布原版自然语言模板，明确主体视角与精确相机参数，再交PE扩写，保留完整JSON编码。新增presence_penalty（默认1.5）、thinking思考模式（默认false）、use_default_template（默认true，使用默认PE系统扩写模板；false仅保留JSON格式约定）、mtp（默认auto，可选off/2/3/4/5）。修改任何选项使PE缓存失效。MTP需模型含对应权重才生效。
两个节点末尾追加镜头预览图IMAGE口，原有端口索引不变。预览由编辑器当前拍摄框导出，无人物时包含场景魔方；最长边1024，按拍摄框比例。它不进入PE或图像编码输入，只用于连接预览图像对照。旧工作流须打开编辑器并应用一次生成独立预览；尚未生成时输出重新打开编辑器并应用的提示图，不再复用缺少魔方的旧姿态参考图。浏览器升级后请Ctrl+F5强制刷新，再打开编辑器应用一次。重新启动ComfyUI并刷新后使用新参数和输出口。

## Qwen2.1 GGUF编码器
新增Fisher Qwen2.1 GGUF CLIP加载器，依赖已安装ComfyUI-GGUF。clip_name选择Qwen3-VL-8B语言GGUF，vision_source选择配套mmproj F16文件；也支持从完整Qwen3-VL-8B safetensors仅读取视觉权重。两个文件置于models/text_encoders。CLIP输出接人物与姿态编码节点的clip，pe_clip保持原接线。新节点需重启ComfyUI加载。适配Qwen3-VL deepstack与双帧patch权重，使用Qwen2.1官方编码路径4096维，不裁剪Klein的12288维输出。配套Heretic GGUF+mmproj已通过参考图编码及320x192一步采样兼容性验证，尚未做完整质量对比。
